# macOS worker sandbox bridge

Independently authored Rust/N-API code under approved route A. This is not recovered vendor native code. `src/lib.rs` exposes `apply(profile)` and throws if policy cannot be applied; there is no permissive fallback. It replaces the former C bridge. The built `.node` file and Cargo target directory are ignored by Git.

Build with `npm run build:sandbox`; this requires macOS Command Line Tools and Rust/Cargo. Set `CUA_CARGO` to override the Cargo executable; otherwise the script uses rustup Cargo when installed, or Cargo on PATH. No Node headers or npm native-build dependency is required. The stable N-API function signatures are checked against the installed Node headers, and the sandbox ABI against the installed macOS SDK. This small bridge directly binds these existing C APIs; it does not reimplement either API. `npm run test:sandbox` builds the addon and restored runtime, then enables the two OS integration tests. Ordinary test discovery skips these opt-in tests.

The trusted sandbox-bootstrap loads only its own bridge before applying the supplied profile, deletes bootstrap profile/addon variables, sets worker argv and imports the worker only after successful application. The launcher's environment must be exact and must exclude untrusted NODE_OPTIONS/preload/DYLD inputs: this module is not yet a complete launcher. Profiles and entry/addon paths are host configuration, never model tool arguments.

Pre-exec deny-default read allowlists made this local Node abort inside dyld ignition startup before JavaScript. The owned crash report showed SIGABRT, namespace 0x23 and ignition_halt/CacheFinder frames. Apple's [XNU reason definitions](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/reason.h) map 35 to LIBIGNITION; this observation does not identify the precise denied loader resource. A read-all diagnostic probe worked, but that broad permission is not used by this implementation. Applying restrictions after trusted Node/addon initialization and before worker code avoids that startup failure while retaining the tested denials.

The two tests passed on this Mac: allowed scratch I/O works; a separate sentinel file, process spawn and loopback connect all fail EPERM, with zero server connections. Actual restored kernel/trusted workers run 42 and a configured RPC under explicit read-only worker/dependency/service roots and separate writable directories. Only metadata of required ancestor paths is granted for canonicalization. Bootstrap settings do not appear in nodeRepl.env.

Apple's installed SDK marks sandbox_init deprecated/unsupported and reserves non-named profile flags. This bridge uses the available custom-profile entry point experimentally; cross-version support and production distribution are not established. It does not reconfigure an already sandboxed process (the API errors), change OS security settings or bypass vendor-service authentication. A production profile builder, read/write root validation, preload/environment scrubbing, actual application service integration, adversarial escape coverage and crash/SIGKILL process containment remain unfinished. Default demo is unchanged.


Rust bridge migration verification: the same OS denial test passes using the
Rust-produced addon. A separate child process verifies missing/extra arguments,
non-string values, empty/oversized/NUL-containing profiles and invalid policies
throw before worker execution. All 29 Rust supervisor tests and both external
sandboxed MCP lifecycle tests pass against the replaced addon. No real browser
or App acceptance is implied. The TS bootstrap only loads this bridge, removes
bootstrap environment settings and imports the JS-derived worker; the policy is
now generated by the Rust supervisor. Production runtime composition and proof
of original sandbox behavior remain open.
