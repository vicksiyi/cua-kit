# @core/native-macos

Independently authored macOS backend, authorized under route A; not recovered vendor-native source. Uses the existing `native/macos` Swift helper and preserves the restored Sky service RPC through `@core/sky/serviceFactory`. The helper/errors transport was reused from the earlier local prototype; the new client adapter and deployment service are distinct from the old MacProvider API.

The demo's `--computer` / `--check-computer` modes default to this backend. Build the helper with `npm run build:native`; default demo commands do this automatically. Override `CORE_CUA_NATIVE_HELPER_PATH` for an explicitly built helper; `CORE_CUA_NATIVE_BACKEND=vendor` retains the installed service route for comparison. There is no automatic fallback.

Implemented adapter slice: running-app inventory, full AX observations with permission-gated window screenshots, AX setValue, focused text input, unheld key chords, text/cursor selection, advertised AX secondary actions, mouse click, scroll and coordinate drag. All App reads/writes require the host approval callback; discovery does not. Bindings are checked against process launch identity after authorization. Actions require the latest complete observed snapshot, are serialized and invalidate the snapshot before dispatch. The helper also revalidates process/snapshot identity.

Current differences: app discovery covers running visible apps only; observation text is the helper's formatting and always full; screenshots return null when Screen Recording is not granted; multiple capturable windows use focused-window geometry/title matching and reject unresolved ambiguity; held mouse input, audio, native supervisor replacement and full original policy parity remain outstanding. Unsupported methods are not advertised by the service. Partial methods do not establish full API equivalence.

The native supervisor is still the installed executable; only the App service backend is replaced at this stage. No installed authentication, signing or TCC setting is modified. Model secrets are not inherited by the helper. On the current machine the helper reports Accessibility=false and ScreenRecording=false. Running-app inventory succeeded directly and through the actual MCP/restored runtime; UI reads/actions remain unaccepted.

Selection routes through restored app.selectText and Sky select_text. The helper locates a unique UTF-16 match using optional prefix/suffix and supports text/cursor_before/cursor_after. Overlapping ambiguity, missing text and invalid modes fail explicitly. Secondary actions route through perform_secondary_action and the existing helper checks each requested AX action against the element's advertised actions (focus uses AXFocused). These methods consume the current snapshot and retain authorization requirements. Swift pure range tests and the restored CUA→service→adapter fixture pass; real App effects remain unverified.

Screenshot integration reuses observeWithScreenshot, which validates AX state before/after capture and window identity/geometry inside the helper. Each app-state request refreshes hello permissions. If screen recording is unavailable, AX-only observation returns screenshot:null with an explicit warning; getScreenshot then reports unavailable through the original CUA binding. Granted capture errors propagate and invalidate the old input snapshot. The adapter checks canonical base64, PNG signature/IHDR, matching dimensions and byte/pixel budgets; it does not implement a complete PNG decoder. Only fixture PNG roundtrip has been tested through the restored getScreenshot; real capture requires OS permission and remains unaccepted.

Multiple-window capture now selects an explicit helper windowId when present, otherwise matches the app's AX focused window against its own ScreenCaptureKit candidates. Matching uses finite geometry within 0.5 points; title only disambiguates equal-geometry candidates. Missing/ambiguous identity is an error, not a first-window fallback. Focus identity/geometry is checked again after capture. Pure tests cover order independence, explicit identity, equal frames, missing focus, unrelated title, and negative screen coordinates. Real multi-display coordinate alignment and focus-change races remain unverified.

Native click now dispatches actual CGEvent mouse-down/up pairs to the bound process (not AXPress). Indexed clicks use the observed AX element center; screenshot clicks use the captured contentRect and actual image dimensions, then recheck window/frame/scale/focus and the AX snapshot. Geometry is included in snapshots so moved elements invalidate input. Supported buttons: left/right/middle and l/r/m; count 1..10; modifier-only key chords. Nonzero duration and nonmodifier held keys remain explicitly unsupported pending input scheduling. Input timeouts are classified ACTION_OUTCOME_UNKNOWN; event dispatch itself is not proof of an application response.

Coordinate basis: Apple documents [SCContentFilter contentRect as screen points](https://developer.apple.com/documentation/screencapturekit/sccontentfilter) and [CGEvent mouse positions as global coordinates](https://developer.apple.com/documentation/coregraphics/cgevent/init(mouseeventsource:mousetype:mousecursorposition:mousebutton:)). Mapping and nonposted event construction pass self-tests; real Retina/multidisplay input acceptance is still pending.

AX observation text preserves parent indices, frame, advertised action names, enabled/focused/selected state and selection ranges from the native helper. This is independent formatting, not the proprietary native serializer. Secure element values are omitted by both helper and adapter. Restored getAXState fixture coverage verifies that models receive this context; real OS observation remains permission-gated.

Scroll now routes restored app.scroll → Sky scroll → independent scrollInput → CGEvent to the bound PID. Indexed targets use their observed scroll-area/window ancestry; screenshot targets use the smallest containing scroll area in the captured window, falling back to the captured window extent. One page is independently defined as that viewport extent on the chosen axis; original native page conversion is unavailable and equivalence is unproven. Positive fractional pages and all eight direction spellings are accepted. Total distance must round to 1..100000 units; events use pixel units in chunks at most 10, with no cursor warp. Input requires current observations/screenshots, retains authorization and invalidates state. Tests construct but do not post events; real scrolling, acceleration/coalescing and Retina page distance remain unverified. Apple API reference: https://developer.apple.com/documentation/coregraphics/cgeventcreatescrollwheelevent .

Drag now routes restored App.drag through Sky to dragInput. Both endpoints must belong to the current screenshot and use its checked window transform. The independent plan is left-down, 20 interpolated left-drag events at 10 ms waits, then left-up; original native timing is unavailable. PID/launch identity is checked before down and every move. Cooperative cancellation/interruption releases at the last dispatched point when process identity remains valid, invalidates the snapshot and reports ACTION_OUTCOME_UNKNOWN. It never sends cleanup to a reused PID. Forced process termination cannot execute cleanup; this remains a limitation. Swift --drag-self-test uses injected event sinks (no OS input) to verify sequence, successful release, cancellation at different steps and identity loss. Real drag-and-drop/text-selection behavior remains unaccepted.
