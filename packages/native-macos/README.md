# @core/native-macos

Independently authored macOS backend, authorized under route A; not recovered vendor-native source. Uses the existing `native/macos` Swift helper and preserves the restored Sky service RPC through `@core/sky/serviceFactory`. The helper/errors transport was reused from the earlier local prototype; the new client adapter and deployment service are distinct from the old MacProvider API.

The demo's `--computer` / `--check-computer` modes default to this backend. Build the helper with `npm run build:native`; default demo commands do this automatically. Override `CORE_CUA_NATIVE_HELPER_PATH` for an explicitly built helper; `CORE_CUA_NATIVE_BACKEND=vendor` retains the installed service route for comparison. There is no automatic fallback.

Implemented adapter slice: running-app inventory, full AX observations with permission-gated window screenshots, AX setValue, focused text input, key chords with bounded hold duration, text/cursor selection, advertised AX secondary actions, mouse click, scroll, coordinate drag and verified text/HTML/Markdown paste. All App reads/writes require the host approval callback; discovery does not. Bindings are checked against process launch identity after authorization. Actions require the latest complete observed snapshot, are serialized and invalidate the snapshot before dispatch. The helper also revalidates process/snapshot identity.

Current differences: app discovery covers running visible apps only; observation text is the helper's formatting and always full; screenshots return null when Screen Recording is not granted; multiple capturable windows use focused-window geometry/title matching and reject unresolved ambiguity; audio, native supervisor replacement and full original policy parity remain outstanding. Unsupported methods are not advertised by the service. Partial methods do not establish full API equivalence.

The native supervisor is still the installed executable; only the App service backend is replaced at this stage. No installed authentication, signing or TCC setting is modified. Model secrets are not inherited by the helper. On the current machine the helper reports Accessibility=false and ScreenRecording=false. Running-app inventory succeeded directly and through the actual MCP/restored runtime; UI reads/actions remain unaccepted.

Selection routes through restored app.selectText and Sky select_text. The helper locates a unique UTF-16 match using optional prefix/suffix and supports text/cursor_before/cursor_after. Overlapping ambiguity, missing text and invalid modes fail explicitly. Secondary actions route through perform_secondary_action and the existing helper checks each requested AX action against the element's advertised actions (focus uses AXFocused). These methods consume the current snapshot and retain authorization requirements. Swift pure range tests and the restored CUA→service→adapter fixture pass; real App effects remain unverified.

Screenshot integration reuses observeWithScreenshot, which validates AX state before/after capture and window identity/geometry inside the helper. Each app-state request refreshes hello permissions. If screen recording is unavailable, AX-only observation returns screenshot:null with an explicit warning; getScreenshot then reports unavailable through the original CUA binding. Granted capture errors propagate and invalidate the old input snapshot. The adapter checks canonical base64, PNG signature/IHDR, matching dimensions and byte/pixel budgets; it does not implement a complete PNG decoder. Only fixture PNG roundtrip has been tested through the restored getScreenshot; real capture requires OS permission and remains unaccepted.

Multiple-window capture now selects an explicit helper windowId when present, otherwise matches the app's AX focused window against its own ScreenCaptureKit candidates. Matching uses finite geometry within 0.5 points; title only disambiguates equal-geometry candidates. Missing/ambiguous identity is an error, not a first-window fallback. Focus identity/geometry is checked again after capture. Pure tests cover order independence, explicit identity, equal frames, missing focus, unrelated title, and negative screen coordinates. Real multi-display coordinate alignment and focus-change races remain unverified.

Native click now dispatches actual CGEvent mouse-down/up pairs to the bound process (not AXPress). Indexed clicks use the observed AX element center; screenshot clicks use the captured contentRect and actual image dimensions, then recheck window/frame/scale/focus and the AX snapshot. Geometry is included in snapshots so moved elements invalidate input. Supported buttons: left/right/middle and l/r/m; count 1..10; modifier-only key chords. Duration is now supported as described below; nonmodifier mouse key chords remain unsupported. Input timeouts are classified ACTION_OUTCOME_UNKNOWN; event dispatch itself is not proof of an application response.

Coordinate basis: Apple documents [SCContentFilter contentRect as screen points](https://developer.apple.com/documentation/screencapturekit/sccontentfilter) and [CGEvent mouse positions as global coordinates](https://developer.apple.com/documentation/coregraphics/cgevent/init(mouseeventsource:mousetype:mousecursorposition:mousebutton:)). Mapping and nonposted event construction pass self-tests; real Retina/multidisplay input acceptance is still pending.

AX observation text preserves parent indices, frame, advertised action names, enabled/focused/selected state and selection ranges from the native helper. This is independent formatting, not the proprietary native serializer. Secure element values are omitted by both helper and adapter. Restored getAXState fixture coverage verifies that models receive this context; real OS observation remains permission-gated.

Scroll now routes restored app.scroll → Sky scroll → independent scrollInput → CGEvent to the bound PID. Indexed targets use their observed scroll-area/window ancestry; screenshot targets use the smallest containing scroll area in the captured window, falling back to the captured window extent. One page is independently defined as that viewport extent on the chosen axis; original native page conversion is unavailable and equivalence is unproven. Positive fractional pages and all eight direction spellings are accepted. Total distance must round to 1..100000 units; events use pixel units in chunks at most 10, with no cursor warp. Input requires current observations/screenshots, retains authorization and invalidates state. Tests construct but do not post events; real scrolling, acceleration/coalescing and Retina page distance remain unverified. Apple API reference: https://developer.apple.com/documentation/coregraphics/cgeventcreatescrollwheelevent .

Drag now routes restored App.drag through Sky to dragInput. Both endpoints must belong to the current screenshot and use its checked window transform. The independent plan is left-down, 20 interpolated left-drag events at 10 ms waits, then left-up; original native timing is unavailable. PID/launch identity is checked before down and every move. Cooperative cancellation/interruption releases at the last dispatched point when process identity remains valid, invalidates the snapshot and reports ACTION_OUTCOME_UNKNOWN. It never sends cleanup to a reused PID. Forced process termination cannot execute cleanup; this remains a limitation. Swift --drag-self-test uses injected event sinks (no OS input) to verify sequence, successful release, cancellation at different steps and identity loss. Real drag-and-drop/text-selection behavior remains unaccepted.

Paste reuses the earlier independent prototype's format preparation (`marked`, `sanitize-html`, `htmlparser2`) and Swift clipboard/paste primitives. These libraries are declared direct package dependencies; no parser was reimplemented. The native helper owns one pasteWithClipboard transaction: validate focused AX editor → preserve all clipboard formats → write temporary text/HTML → Command+V and AXValue verification → restore. This removes caller-side lease restoration dependencies. Externally changed clipboard content is preserved and reported as incomplete restoration, never silently overwritten or reported fully restored. A failed/incomplete paste consumes the old observation. Custom editors without readable AXValue/selection, secure fields and no-observable-change pastes are not accepted; rich formatting itself is not verified, only expected text. Forced helper termination can still prevent restoration. Named-pasteboard self-tests never touch the user's general clipboard; real App paste remains unaccepted.

## Real owned-App acceptance

Run `npm run test:native:restored` from the repository in a macOS terminal granted Accessibility and Screen Recording. The explicit gate fails when permissions are absent; it does not silently skip or change TCC settings. It launches only CuaFixture --acceptance and authorizes only that child PID. The restored CUA→Sky→independent helper path checks real AX/PNG capture, setValue, indexed and screenshot-coordinate click, Unicode typing, selection, key chord, plain-text paste, actual NSScrollView offset and drag events received by an owned NSView. It is not a DeepSeek/MCP or existing-Chrome acceptance test, and drag-event receipt does not prove arbitrary drag-and-drop support. Rich paste appearance is not covered. The general clipboard is temporarily used only if the gate reaches paste; its native restoration contract remains required.

The PNG-coordinate test uses the AX window frame and PNG dimensions independently of the helper's contentRect conversion. Evidence is written to `/tmp/cua-native-live-evidence.json` (override CUA_NATIVE_EVIDENCE_PATH). The current run is blocked before fixture launch: Accessibility=false, ScreenRecording=false, passed=[]. Gate code/type checking and Swift fixture build passed; none of these UI acceptance assertions has yet passed on this machine.

Held keyboard/mouse input now accepts the restored 0..30000 ms duration range (Sky seconds; native keyboard milliseconds). Each mouse click in a multi-click sequence receives that hold duration; this repetition timing is an independent policy, not native-source equivalence. Cooperative interruption attempts release to the same live process and reports unknown outcome. Forced termination still cannot guarantee release. The helper deadline includes requested hold time, including click count; callers must also provide an outer JS/MCP timeout long enough for the whole operation. No OS key-repeat synthesis is added. set_value, type_text and press_key now return void in the adapter as declared by Sky. Self-tests inject event sinks and wait functions, so real held-input behavior remains unaccepted.

Key parsing now accepts the original documented Control_L/Super_L examples, common left/right modifier suffixes as semantic flags, whitespace around '+', lowercase space and X-style navigation names. Added F1–F20, KP_Enter, ISO_Left_Tab and US ANSI punctuation/keysym names (including literal '+' chords). Mouse modifier parsing shares the alias normalization. Mappings use the installed Apple Carbon key constants; no third-party parser was reimplemented. Remaining gaps: side-specific physical modifier events, complete X keysym coverage and non-US layout translation are not implemented. Use typeText for Unicode text. Swift pure checks cover documented examples, shifted punctuation, aliases and malformed chords; real keyboard effects remain unverified.

### Operator permission setup

From the repository in the terminal that will run the desktop demo:

```sh
npm run permissions:computer
npm run check:computer-permissions
```

The first command builds the helper and explicitly requests the standard macOS Accessibility/Screen Recording dialogs. The operator must grant the permissions in System Settings; this does not write TCC databases or grant access automatically. Use the application named by macOS, since permission attribution can differ between Terminal, a GUI agent and a tmux-launched process. Restart the responsible app/terminal if macOS asks. The check prints both booleans and exits 2 until both are true, without requesting dialogs. A successful check in one launcher does not prove that another launcher has the same permissions. Recheck the actual MCP/helper runtime before desktop acceptance.

### Real DeepSeek desktop acceptance

`npm run test:native-deepseek` builds current native/restored runtime artifacts and explicitly runs the opt-in real-model acceptance gate. It fails before launching any app or requesting the model if either OS permission is absent. With permissions, it creates an owned initially stopped .app, authorizes only that unique bundle, asks real DeepSeek through restored MCP/CUA to open it, enter a random marker, click Save fixture, read the result and capture a screenshot. Independent native AX and PNG checks verify the saved state; matching text in the model answer alone cannot pass. Cleanup targets only that bundle/path. This acceptance is prepared and type-checked but has not run past the permission gate on the current host.
